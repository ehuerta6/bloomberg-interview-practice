# 03 — Double Cancellation

**Type:** Engineering ticket · **Difficulty:** Hard · **Target time:** 45–60 minutes

## Ticket

Two cancellation requests for the same placed order arrive at nearly the same time. Both may report success, restoring the order's units to stock twice.

Only one cancellation should succeed. It should mark the order `cancelled` and restore each line's quantity once. A competing or later request should return a conflict without changing stock. If restoring stock fails, leave both the order and all product quantities unchanged. Only the shopper who placed the order may cancel it.

Place an order with two products, then submit overlapping cancellation requests as `shopper-river`. Use a deterministic synchronization point in the regression test rather than sleeps. Check both responses, the saved order status, and stock for each product before and after. Cover repeated cancellation, failed restoration, ownership, and the normal path.

Add the regression test, correct the cancellation behavior, and run the focused tests and Marketplace suite.
