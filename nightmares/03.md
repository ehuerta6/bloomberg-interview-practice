# 03 — Double Cancellation

**Type:** Engineering Ticket · **Difficulty:** Hard · **Target time:** 45–60 minutes

This original CIC exercise is grounded in Cappy Marketplace, not an official Bloomberg interview question.

## Ticket

Two cancellation requests for the same placed order arrive at nearly the same time. Both callers can be told that cancellation succeeded, and the returned units may be added to available stock twice. A shopper who cancels one order must not create inventory that was never received.

## Expected behavior

- At most one cancellation of a placed order succeeds.
- The successful cancellation changes the order to `cancelled` and restores each order line's quantity exactly once.
- A competing or later cancellation receives a conflict and has no inventory side effect.
- A failed restore leaves the order and every product's stock unchanged.
- Only the owning shopper may cancel the order.

## Reproduction and work

Place an order containing two products, then submit overlapping cancellation requests for its ID as `shopper-river`. Use a deterministic synchronization point in the regression test; do not coordinate the race with sleeps. Record both responses, the persisted order status, and the before/after stock for every line.

Trace the cancellation state transition and inventory writes through the API and SQLite transaction. Add a regression test for the overlap and retain coverage for repeated cancellation, failed restoration, ownership, and normal cancellation. Make the narrow correction and explain why the state and stock cannot diverge.
