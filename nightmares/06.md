# 06 — Payment Error Handling

**Type:** PR Review · **Difficulty:** Hard · **Target time:** 30–45 minutes

This original CIC exercise uses the Marketplace's local payment-outcome simulator; it does not contact a payment provider.

## Scenario

A proposed checkout refactor handles all unsuccessful payment outcomes through one decline path. A temporary processing error is therefore reported and persisted like a definitive decline. The included tests accept a broad range of error responses and do not establish the distinction or its effect on saved checkout attempts.

## Review deliverable

Inspect the actual diff and assess payment outcome classification, HTTP responses, saved attempt state, retry/replay behavior, and order/inventory side effects. Report actionable findings with evidence and severity. Explain which tests pass and what they fail to prove. Recommend focused assertions that distinguish a temporary error from a definitive decline without building a replacement payment system.
