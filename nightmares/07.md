# 07 — Partial Checkout Failure

**Type:** Engineering ticket · **Difficulty:** Hard · **Target time:** 45–60 minutes

## Ticket

A persistence error during checkout can leave changed stock or an incomplete order even though the shopper receives an error.

## Expected behavior

- Checkout either persists a complete valid order, deducts all matching inventory, clears the cart, and records its attempt, or has no checkout side effects.
- A failure during order-line persistence leaves no partial order, stock deduction, cart change, or misleading successful attempt.
- A controlled persistence failure is reported as HTTP 503 so the caller can distinguish an unavailable checkout from a rejected payment.
- The failure must be reproducible through controlled failure injection, without timing assumptions.
- Successful checkout, payment failures, insufficient stock, and idempotent replay keep their existing behavior.

Add a focused regression using a deterministic database failure. Assert the affected persisted state, correct the issue, and run the Marketplace suite.
