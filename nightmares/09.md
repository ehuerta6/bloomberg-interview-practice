# 09 — Cart Update Race

**Type:** Engineering Ticket · **Difficulty:** Hard · **Target time:** 45–60 minutes

This original CIC exercise is grounded in Cappy Marketplace, not an official Bloomberg interview question.

## Ticket

Two requests add quantity to the same cart line at nearly the same time. Both requests may read the same starting quantity and persist a result that loses one valid increment. The shopper's final cart can therefore contain fewer items than the accepted updates imply.

## Expected behavior

- Each accepted add increments the existing quantity exactly once, even when requests overlap.
- Stock limits still apply to the combined quantity; an update that exceeds stock is rejected without a partial write.
- `PUT` continues to set a quantity, while `POST` continues to add to it.
- Other shoppers' carts remain independent.

Trace the cart read/modify/write path through SQLite. Add a deterministic concurrency test with controlled synchronization, not sleeps, and assert both HTTP outcomes, persisted quantity, and stock-boundary behavior. Make a narrow correction and explain the persistence guarantee.
