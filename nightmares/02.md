# 02 — Inventory Validation

**Challenge:** 02

**Type:** Pull request review

**Difficulty:** Medium–Hard

**Target time:** 30–45 minutes

This is an original CIC practice exercise, not an official Bloomberg interview question.

An admin adjusts stock after a delivery or a physical count. Incorrect inventory can make the storefront show the wrong availability and cause checkout to make decisions from a stale count.

## Pull request

**Title:** Review: admin inventory adjustment changes

**Pull request summary:** The PR proposes a focused update to admin inventory adjustments and adds related tests for reviewers to assess.

An admin can apply a signed integer delta to a product's stock. For example, a delta of `+3` adds three units and `-2` removes two. The resulting quantity is returned to the caller.

### Claimed behavior

- A valid adjustment changes stock by exactly the requested delta.
- A rejected adjustment leaves stock unchanged.
- The returned stock matches the persisted quantity.

### Acceptance criteria

- A successful adjustment keeps stock between zero and the SQLite integer maximum.
- Zero deltas, invalid values, unknown products, and changes that would underflow or overflow are rejected with the documented response.
- If two valid adjustments target the same product at the same time, both accepted deltas are reflected in final stock. Neither update overwrites the other.
- Existing admin authorization and shopper access behavior remain unchanged.

For a concrete case, start with 12 units and apply `+3` and `+4` at the same time. If both requests succeed, final stock must be 19.

## Review deliverable

Review the exact proposed diff and its tests. Deliver:

1. Actionable findings ordered by severity. For each, include the relevant file and line, triggering input or state, violated contract, and evidence for the impact.
2. Stronger tests that distinguish the claimed behavior from incorrect behavior, including the concurrent adjustment case above.
3. A short assessment of what the included tests establish and leave unproven.

This is a code review exercise. Do not submit a full corrected implementation.

### Review questions

- What should final stock reflect when multiple adjustments overlap?
- Which input orderings and state changes should tests cover for accepted adjustments?
- Do the tests verify an exact resulting value and persisted state, or only a plausible response for an ordinary input?
- Which invalid values and inventory boundaries need explicit coverage?
- Does a failed or conflicting request leave stock unchanged?

### Non-regression expectations

Existing success, underflow, overflow, invalid-payload, unknown-product, and authorization behaviors must remain intact. Accepted adjustments must not be lost, duplicated, or applied to the wrong product.
