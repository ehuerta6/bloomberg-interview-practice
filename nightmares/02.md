# 02 — Inventory Validation

**Type:** Pull request review · **Difficulty:** Medium–Hard · **Target time:** 30–45 minutes

An administrator uses stock adjustments after deliveries and inventory counts. Review this change before it ships to confirm accepted adjustments leave inventory accurate.

## Pull request

**Title:** Admin inventory adjustments

The endpoint accepts a signed integer delta and returns the resulting stock quantity. For example, `+3` adds three units and `-2` removes two.

### Requirements

- A valid adjustment changes stock by exactly the requested delta.
- A rejected adjustment leaves stock unchanged.
- The returned stock matches the persisted quantity.
- A successful adjustment keeps stock between zero and the SQLite integer maximum.
- Zero deltas, invalid values, unknown products, and changes that underflow or overflow are rejected with the documented response.
- Concurrent requests follow the same quantity and stock rules as sequential adjustments.
- Existing admin authorization and shopper access behavior remain unchanged.

## Review request

Review the exact proposed diff and its tests. Deliver:

1. Findings ordered by severity, with the relevant file and line, triggering input or state, violated contract, and evidence.
2. Focused tests that verify returned and persisted quantities, including concurrent requests.
3. A brief assessment of what the included tests establish and leave unproven.

Do not submit a replacement implementation. Preserve existing success, underflow, overflow, invalid-payload, unknown-product, and authorization behavior. Accepted adjustments must not be lost, duplicated, or applied to the wrong product.
