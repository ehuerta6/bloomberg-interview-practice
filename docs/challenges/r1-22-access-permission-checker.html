22 · Access Permission Checker

PR: Enforce access rule precedence

Summary

A document service combines role grants, direct user overrides, and ownership. Review the precedence rules carefully because an incorrect allow can expose protected data.

Input and output

has_permission(user, action, resource, acl) receives a user ID and roles, role grants, direct per-user allow/deny rules, and resource owners. It returns a boolean.

Expected behavior and invariants

  • A direct user deny blocks the action even if a direct allow or role grant also exists. Both resource-specific and * rules are supported.
  • A direct allow grants access when no deny matches.
  • Otherwise any matching role grant allows the action. Role rules may target the resource or *.
  • A resource owner may read that resource, but ownership does not grant write or other actions. Unknown users are denied.

Review task

Construct conflicting direct and role rules. Verify deny precedence across wildcard and resource-specific entries, then check ownership and unsupported actions.
