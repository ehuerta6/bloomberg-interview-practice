24 · Data Merge Reconciliation

PR: Reconcile customer snapshots and tags

Summary

Two import feeds contain customer snapshots, while tags are accumulated independently. Review how timestamps choose fields and how shared metadata survives reconciliation.

Input and output

merge_records(existing, incoming) accepts ordered lists of customer dictionaries with customer_id and ISO-sortable updated_at fields, plus optional tag lists. It returns a new ordered list.

Expected behavior and invariants

  • Keep existing customer order. Append previously unseen customers in their first incoming order.
  • For matched customers, a newer timestamp supplies the ordinary fields; an equal timestamp prefers incoming fields; an older snapshot does not replace current fields.
  • Tags are a stable union of existing then incoming values, without duplicates, regardless of which snapshot wins.
  • Do not mutate either input or share mutable tag lists with the result.

Review task

Compare newer, older, and tied snapshots. Exercise duplicate tags and verify both inputs and nested tag arrays remain isolated.
