19 · Feature Flag Evaluation

PR: Evaluate feature rollouts consistently

Summary

A rollout service needs to evaluate global state, explicit user lists, and stable percentage cohorts. Review precedence and boundary behavior.

Input and output

evaluate_flag(flag, user) receives an enabled flag, optional allowlist and denylist, and optional rollout percentage, plus a user dictionary with a stable user_id. It returns a boolean.

Expected behavior and invariants

  • A globally disabled flag is always off.
  • A denylisted user is off even if also allowlisted. An allowlisted user is on otherwise.
  • Other users enter a stable bucket from 0 through 99 derived from SHA-256 of their ID; enable them when the bucket is less than the percentage.
  • Percentages must be numeric and between 0 and 100. Missing user IDs are off.

Review task

Test precedence before rollout, exact bucket boundaries, stable results across calls, malformed percentages, and users without IDs.
